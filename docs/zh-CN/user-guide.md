# 票夹普通使用指南

[中文](user-guide.md) · [English](../en/user-guide.md) · [项目首页](../../README.md)

本指南面向只使用票夹、不修改代码的人。程序在本机运行；订单数据、发票和淘宝登录会话不会自动同步给其他人。

## 1. 首次安装

1. 安装 Node.js 22.13 或更新版本。
2. 下载并解压 GitHub 仓库。
3. macOS 双击 `Setup.command`；Windows 双击 `Setup.bat`。首次安装会下载程序依赖和 Chromium，可能需要几分钟。
4. 打开 `engine/invoice-config.json`，填写你自己的发票抬头、税号和邮箱。不要把这个文件发给别人或上传到 GitHub。
5. 双击 `Start.command`（macOS）或 `Start.bat`（Windows）。终端窗口保持打开，在浏览器访问 <http://127.0.0.1:4318>。

淘宝登录和验证码只能在弹出的本机浏览器中由你自己完成。不要共享浏览器会话目录。

## 2. 建立 Event 并扫描

1. 在 Event 页面新建 Event，填写名称和购买日期范围。
2. 打开 Event，检查日期范围正确后点击“扫描订单”。
3. 扫描时留意弹出的淘宝浏览器，按提示完成登录或安全验证。
4. 在任务记录查看进度；回到订单记录查看每笔订单的状态、金额和备注。

**扫描会产生真实淘宝操作：**脚本会检查订单和客服最近消息，尝试下载可确认的 PDF；若发现客服发来的发票申请卡片，会尝试填写并提交。扫描不会发送客服聊天消息。普通系统申请入口不会由批量扫描直接提交。单笔“检查此订单”也可能处理并提交客服申请卡片。

只对你有权处理的账号和订单使用。遇到结果不确定、页面异常或任务中断时，先在淘宝核对，再决定是否重试，避免重复申请。

## 3. 状态与发票

- **已开票（绿色）**：订单有已关联发票附件；订单行可显示“查看发票 ↗”。
- **系统开票中（黄色）**：系统申请入口显示正在处理。
- **客服开票中（蓝色）**：已通过客服流程提交申请，等待商家处理。
- **待确认（红色）**：状态或附件需要人工核对。客服 PDF 金额与订单金额不一致时，PDF 仍保存，可在“查看详情”查看；备注会说明金额不一致，订单不会标记为已开票。
- **手动录入（紫色）**：订单由用户手动补录。

在订单“查看详情”中可以打开 PDF 或图片。订单行的“查看发票 ↗”只在状态含“已开票”且关联附件时出现。

## 4. 手动编辑、上传与校对

1. 点击“编辑订单”，可修改状态、备注、金额和“是否导出”。
2. 可上传或粘贴 JPG、PNG、PDF，单个文件最大 20 MB。上传附件后可同时把状态设为“已开票”；保存后在详情中查看附件。
3. 点击“校对”，原搜索框会切换为金额清单输入。金额可用换行、空格、逗号或分号分隔。系统将清单与当前 Event 中已勾选“是否导出”且状态为“已开票”的订单按金额和重复次数核对。未出现在清单中的订单会显示在表格中。
4. 点击“退出校对”返回普通店铺、订单号或金额搜索。

## 5. 导出发票

点击“导出”，勾选带有发票附件的订单，再点击导出选中。浏览器会保存 ZIP 文件；成功生成后，这些订单会记录导出状态和时间。导出只包括本机已经关联的 PDF/JPG/PNG 文件。

## 6. 停止、备份与隐私

- 保持启动票夹的终端窗口打开。按 `Ctrl+C` 停止服务；正在进行的淘宝操作可能中断，停止后先核对淘宝状态。
- 重要数据包括 `ui/.data/events.json`、`engine/downloads/`、`engine/invoice-config.json`。停止服务后可把它们备份到安全位置。备份含订单、税号及发票信息，应加密保护，不要发到聊天或公开仓库。
- 不要把 `engine/.playwright-browser/` 登录会话目录分享给他人。
- GitHub 仓库不会自动共享订单和发票。每位使用者使用自己电脑上的数据。

## 常见问题

- **网页打不开**：确认 Start 窗口还在运行，再打开 `http://127.0.0.1:4318`。
- **脚本提示找不到配置**：确认 `engine/invoice-config.json` 已从样例创建并填写。
- **扫描触发验证码**：在弹出的淘宝浏览器人工完成验证；不要在票夹里输入验证码。
- **PDF 无法核对金额**：仍可在详情中检查已保存文件；需要人工确认其内容和订单归属。
- **电脑休眠或服务关闭**：任务不会继续运行。重新启动后先查看淘宝和任务结果，再决定是否重扫。
